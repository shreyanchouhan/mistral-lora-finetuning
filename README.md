# Domain-Specific LLM Fine-Tuning with LoRA (Mistral-7B)

Instruction-tune **Mistral-7B-Instruct** on a 10,000-pair technical-reasoning
dataset using **LoRA / QLoRA**, mixed-precision training, and gradient
checkpointing — designed to run on a free Colab T4 GPU.

The same code path works on smaller causal LMs (TinyLlama, GPT-2) for
local smoke-testing on CPU or low-VRAM GPUs.

## Highlights

- **LoRA** rank-16 adapters on attention projections — only ~0.5% of params trained
- **4-bit NF4 quantization (QLoRA)** for 7B-class models on 16 GB consumer GPUs
- **Mixed-precision** training (bf16 / fp16)
- **Gradient checkpointing** to cut activation memory ~30%
- **Paged AdamW 8-bit** optimizer for lower optimizer-state VRAM
- **Chat-template formatting** auto-selected per model family
- **Programmatic 10k instruction dataset** — DSA, ML/DL, system design, debugging, math

## Quickstart — recommended path: Colab

Mistral-7B fine-tuning needs ~12 GB VRAM. Free Colab T4 has 16 GB, fits QLoRA.

1. Zip this repo: `Compress-Archive -Path mistral-lora-finetuning -Dest mistral-lora-finetuning.zip`
2. Open `colab_train.ipynb` in Colab (Runtime → Change runtime type → T4 GPU)
3. Upload the zip when the notebook prompts you
4. Run all cells — generates data, QLoRA-trains for ~45-60 min, evaluates,
   lets you download the trained adapter

## Local smoke test (proves the pipeline)

```bash
# Python 3.10 – 3.13
py -3.13 -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt

# 1. Build the dataset
python data/build_dataset.py

# 2. Train (GPT-2 fits in CPU / any GPU)
python src/train.py --model gpt2 --max_steps 50 \
    --per_device_train_batch_size 2 --max_seq_length 256

# 3. Compare base vs fine-tuned
python src/evaluate.py --model gpt2 --adapter outputs/lora-adapter --limit 30

# 4. Chat
python src/inference.py --model gpt2 --adapter outputs/lora-adapter
```

| Metric                    | Value          |
|---------------------------|----------------|

| Base token-overlap F1     | 0.031          |
| Fine-tuned F1             | 0.040          |
| **Relative improvement**  | **+31.2 %**    |

Token-overlap F1 is a lightweight proxy — swap in MT-Bench / IFEval for a

## Dataset

10,000 programmatically generated supervised prompt–response pairs:

- **DSA / algorithms** — sorting, graphs, DP, data structures
- **System design** — caching, sharding, queues, consistency
- **ML / DL** — gradient descent, attention, transformers, regularization
- **Debugging** — common Python / CUDA / training failure modes
- **Math** — arithmetic and probability word problems
- **Code** — clean Python implementations of canonical algorithms

Fully reproducible offline via `python data/build_dataset.py` (seed=42).

## Techniques applied (from the CV bullet)

> *Fine-tuned Mistral-7B language model using LoRA on domain-specific
> instruction datasets for technical reasoning.*

- LoRA rank-16 with `q_proj, k_proj, v_proj, o_proj` (auto-detected per model)
- QLoRA path: 4-bit NF4 base, double quantization, paged 8-bit AdamW

> *Constructed supervised instruction dataset with 10,000 prompt-response pairs.*

- `data/build_dataset.py` — 10,000 train + 200 eval, JSONL, deterministic seed

> *Implemented mixed-precision training and gradient checkpointing.*

- bf16/fp16 selected automatically per device capability
- `gradient_checkpointing=True` in `configs/default.yaml`

> *Evaluated base versus fine-tuned models.*

- `src/evaluate.py` runs both and writes `outputs/eval_report.json`
